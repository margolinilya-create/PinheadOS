## Состояние на 2026-10-05 (сессия 78) — правки ERP 05.10: восемь пунктов

владельца: старые этапы, закрытые с нулём и без отчётов, «пропускают вход»; одна ветка,
три этапа (1–3 → 4–5 → 6–8); миграции применять к боевой базе с пробой и откатом.
Пп. 4–5 и 6–8 делали два агента в отдельных копиях репозитория, ветки слиты.

### Что сделано

- **П. 1, факт вместо плана.** Выход этапа — `qty_done`; прозрачный этап
  (`erp_item_stages.qty_passthrough`: пропущенный, непроизводственный, файловый, старый
  закрытый с нулём — разметка миграции, 136 из 318 этапов) передаёт свой вход. Потолок
  сдачи — вход этапа; «не учтено» — от принятого, когда предшественники закрыты; маршрут
  показывает недовыпуск; склад ГП и отгрузка — не больше выпущенного (`erp_item_produced_qty`,
  `erp_ship_order`). `stageDonePatch` пишет принятое, а не тираж. Попутно:
  `SendToContractorCard` звал `stageInputQty` с неверными аргументами.
- **П. 2, сетка.** `loadAll` не затирает деталь (`mergeListOverDetail`); стандартная шкала
  больше не подставляется, размер вне заказа — только руками.
- **П. 3, повторная сдача.** Колонки «Сдано ранее / Брак ранее / Переделка ранее», «в работе N»
  по строке (`sizeLedger`); стоимость сборки стартует записанной; после сдачи `loadOne`.
- **П. 4, приёмка рулонов.** `AcceptMaterialForm` в широкой панели: строка на рулон с подписями
  и единицами, «расчёт»/факт, сумма весов = поставке, разница с заказанным, итог и «Принять»
  в закреплённом низу (`drawerFooter`), история поставок с рулонами (`ReceiptHistory`).
- **П. 5, закрой.** Строка рулона: исходный метраж (источник) · записано · доступно; «Завершить
  рулон» — отдельное окно (`RollFinishModal`, без предвыбора; замер через
  `erp_material_roll_set_params`, судьба — `erp_roll_set_leftover`); пока открыта форма записи,
  нет кнопок закрытия этапа и смены цеха. Текст гейта судьбы остатка обновлён миграцией.
- **П. 6, закупка.** Карточка в `Drawer wide` по `?supply=`, параметры списка в адресе

  заказано / принято», детали строки раскрываются; в «Новой закупке» нет «Фактического
  количества», поля группами, заказ предвыбран.
- **П. 7, закупка → приёмка.** «Принять поставку» / «Открыть приёмку» в строке материала

- **П. 8, склад.** Вкладки (материалы / готовые изделия / подряд / отгрузка / все), кнопка по
  операции, поиск по всем задачам, фильтр сроков, срок поставки (`eta_date`, «не задан»),
  состояние в адресе. `Warehouse.jsx` 510 → 254 строки.

### Миграции

Применены: `20261005074459_erp_stage_fact_flow` (проба begin…rollback на живой позиции:
70 → 68 → 60, ВТО получает 60, 61 отклоняется, закрытие с нулём после правки не
прозрачно), `20261005083947_erp_rolls_fate_text`. Затем `20261005092131_erp_stage_fact_flow_fixes` — две находки
ревью безопасности: потолок факта выводит прозрачность из `is_production` участка, а не
из присланного `qty_passthrough`; отгрузка берёт advisory-блокировку по позиции (две
параллельные попытки не превысят выпущенное). И `20261005092736_erp_clamp_trusted_state`: исключение
из потолка — только если этап прозрачен и до, и после правки; потолок проверяется при росте
числа, выходе из `skipped`, смене цеха и вставке с фактом (проба с откатом: «skipped + 999»
отклонён, обычная сдача 70 проходит, 71 — нет, закупка без потолка). Затем `20261005093609_erp_clamp_new_row`: потолок считается
по НОВОЙ строке и только по предшественникам той же позиции, проверяется и при смене
`depends_on`/`item_id`, в функции один отказ (проба: ссылка на чужой этап отклонена). И `20261005094126_erp_input_same_item`: обход входа этапа
идёт только по этапам той же позиции. Находку «признак `qty_passthrough` пишет клиент»
не принимаем: сохранённое значение всегда пересчитывает триггер `erp_stage_passthrough`. Инструмент применения держит на скрытом
подтверждении текст с `drop trigger`/`disable trigger` — первая проба упала по таймауту;
переписано на `create or replace trigger` и разметку до триггера.

### Продолжение 09.10 — обход в браузере и правки по нему

Ветка `claude/project-feedback-knzk2j`. Агент `pinhead-qa` прошёл правки 01.10/05.10
на e2e-моке (входа на бой в контейнере нет: ни `.env`, ни учётки). Исправлено:
- **Последняя партия кроя снова не сдавалась** — клиентский гейт
  (`completionBlockFor` → `stageCompletionBlock`) спрашивал судьбу остатков и при
  сдаче, хотя сервер с 08.10 спрашивает её только при закрытии. Сдача
  (`submitStageReport`) передаёт `batch`, судьба остатков — только «Завершить этап».
- **Частичная приёмка закрывала задачу склада** — `awaitsAcceptance` считал
  `accepted_partial` концом. Теперь задача открыта до полной приёмки; закупка
  у частично принятой позиции показывает «Принять поставку» и при закрытой задаче
  (задачи, закрытые до правки, на складе остаются закрытыми — их видно во «Все»).
- Escape больше не закрывает `UserModal`, `PlanAddModal`, `RollFinishModal`.
- Замер, расходящийся с записями, требует причину (`rollFinishBlock(…, reason)`).

Не взято (замечания QA): кнопки «Завершить рулон» нет на экране задания (только в форме
записи); «Обновить приёмку» у второй поставки; обрезанный заголовок «Материал и цвет»;
колонка «Расчётный метраж» шире 1440 px. Скриншоты отчёта — в scratchpad сессии.
