## Состояние на 2026-09-27 (сессия 71) — «Новый заказ» на устаревшей вкладке

Ветка `claude/new-order-error-w98cfk`. Владелец прислал снимок: нажатие
«Новый заказ» даёт «Не удалось загрузить экран (Failed to fetch dynamically
imported module: …/assets/CreateOrderModal-CtVzS8xJ.js)» с кнопкой «Повторить».

### Разбор

- Это НЕ поломка формы и не связь: вкладка открыта до выкатки #183, чанк формы
  (она едет отдельным файлом с сессии оптимизации) исчез под прежним именем.
  Распознавание «вышло обновление» в проекте было — `lib/appUpdate`,
  полноэкранный `ErrorBoundary`, `unhandledrejection` в `main.jsx`, — но
  локальный фолбэк оболочки ERP (`ErpApp.jsx`) собирал текст сам, мимо него:
  сырой текст браузера, совет «проверьте связь» и «Повторить», который при
  отказе `React.lazy` не делает ничего (отказ запоминается до перезагрузки).
- Service worker ни при чём: навигация у него «сначала сеть», 404 ассетов
  не кешируется (проверено по `public/sw.js`).

### Что сделано

- `ErpStates.UpdateAvailable` — состояние «Вышло обновление приложения» с
  кнопкой «Обновить» (тексты общие с `lib/appUpdate`); перезагрузка только
  по нажатию — в соседней форме может быть набранное.
- `ErpStates.ScreenCrashed` — единый фолбэк границы экрана: пропавший чанк →
  `UpdateAvailable`, настоящее падение → прежний `LoadFailed` с текстом
  ошибки и «Повторить». `ErpApp` подключён к нему.
- `isChunkLoadError` знает и «Unable to preload CSS for …» (Vite: пропал
  CSS-файл чанка) — второй снимок владельца, полноэкранная граница
  показывала «Что-то пошло не так».
- Тесты: `ErpStates.test.jsx` (обе ветки, отрицательная — обычная ошибка
  кода остаётся видимой) и сторож проводки `erp/screenCrashed.test.ts`
  (тест компонента был бы зелёным при возврате рукописного фолбэка в `ErpApp`).

### Вторая часть (PR после #184): плашка ДО ошибки

Владелец: «Почему эти ошибки есть?» — потому что вкладка узнавала о выкатке
первым сломанным импортом. Теперь узнаёт заранее:

- `vite.config.js` зашивает маркер сборки (`__BUILD_ID__`: коммит Vercel,
  иначе момент сборки) в код и кладёт его же в `dist/version.json` —
  из ОДНОЙ переменной (сторож в `lib/appVersion.test.ts` читает конфиг).
- `lib/appVersion.startVersionWatch` (из `main.jsx`, только PROD): при
  возврате вкладки на экран и раз в 5 минут читает `/version.json`
  с `no-store`; маркеры разошлись → `useAppUpdateStore.markAvailable()`,
  наблюдение останавливается. Отказ сети / HTML вместо JSON / пустое поле —
  «не знаем», не обновление. Файл вне `/assets/` — service worker его
  не кеширует (сторож читает `CACHED_PREFIXES` из `sw.js`).
- `components/shared/UpdateBanner` в `GlobalHosts` (`App.jsx`): плашка
  снизу слева, `role="status"` с именем «Обновление приложения», регион
  смонтирован всегда; «Обновить» перезагружает, «Позже» прячет на 30 минут
  (`SNOOZE_MS`), потом возвращается сама. Не перезагружаем без нажатия.
- Прежние обработчики (`appUpdate`, `ScreenCrashed`) остаются второй линией:
  вкладка, ушедшая в фон до выкатки и вернувшаяся кликом по ленивой кнопке,
  всё ещё может упереться в отказ раньше проверки.
