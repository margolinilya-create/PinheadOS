## Состояние на 2026-10-05 (сессия 78) — правки ERP 05.10: восемь пунктов

Ветка `claude/rules-5-10-ix6lze`. Документ владельца «правки реп» (05.10). Решения
владельца: старые этапы, закрытые с нулём и без отчётов, «пропускают вход»; одна ветка,
три этапа (1–3 → 4–5 → 6–8); миграции применять к боевой базе с пробой и откатом.
Пп. 4–5 и 6–8 делали два агента в отдельных копиях репозитория, ветки слиты.

### Что сделано

- **П. 1, факт вместо плана.** Выход этапа — `qty_done`; прозрачный этап
  (`erp_item_stages.qty_passthrough`: пропущенный, непроизводственный, файловый, старый
  закрытый с нулём — разметка миграции, 136 из 318 этапов) передаёт свой вход. Потолок
  сдачи — вход этапа; «не учтено» — от принятого, когда предшественники закрыты; маршрут
  показывает недовыпуск; склад ГП и отгрузка — не больше выпущенного (`erp_item_produced_qty`,
  `erp_ship_order`). `stageDonePatch` пишет принятое, а не тираж. Попутно:
  `SendToContractorCard` звал `stageInputQty` с неверными аргументами.
- **П. 2, сетка.** `loadAll` не затирает деталь (`mergeListOverDetail`); стандартная шкала
  больше не подставляется, размер вне заказа — только руками.
- **П. 3, повторная сдача.** Колонки «Сдано ранее / Брак ранее / Переделка ранее», «в работе N»
  по строке (`sizeLedger`); стоимость сборки стартует записанной; после сдачи `loadOne`.
- **П. 4, приёмка рулонов.** `AcceptMaterialForm` в широкой панели: строка на рулон с подписями
  и единицами, «расчёт»/факт, сумма весов = поставке, разница с заказанным, итог и «Принять»
  в закреплённом низу (`drawerFooter`), история поставок с рулонами (`ReceiptHistory`).
- **П. 5, закрой.** Строка рулона: исходный метраж (источник) · записано · доступно; «Завершить
  рулон» — отдельное окно (`RollFinishModal`, без предвыбора; замер через
  `erp_material_roll_set_params`, судьба — `erp_roll_set_leftover`); пока открыта форма записи,
  нет кнопок закрытия этапа и смены цеха. Текст гейта судьбы остатка обновлён миграцией.
- **П. 6, закупка.** Карточка в `Drawer wide` по `?supply=`, параметры списка в адресе
  (`hooks/useListParams`), сводка строкой, таблица 8 колонок без горизонтали, «нужно /
  заказано / принято», детали строки раскрываются; в «Новой закупке» нет «Фактического
  количества», поля группами, заказ предвыбран.
- **П. 7, закупка → приёмка.** «Принять поставку» / «Открыть приёмку» в строке материала
  (`utils/receiptLink`), склад открывает задачу по `?task=`, «← К закупке» возвращает с теми же
  параметрами; список поставок в деталях строки.
- **П. 8, склад.** Вкладки (материалы / готовые изделия / подряд / отгрузка / все), кнопка по
  операции, поиск по всем задачам, фильтр сроков, срок поставки (`eta_date`, «не задан»),
  состояние в адресе. `Warehouse.jsx` 510 → 254 строки.

### Миграции

Применены: `20261005074459_erp_stage_fact_flow` (проба begin…rollback на живой позиции:
70 → 68 → 60, ВТО получает 60, 61 отклоняется, закрытие с нулём после правки не
прозрачно), `20261005083947_erp_rolls_fate_text`. Затем `20261005092131_erp_stage_fact_flow_fixes` — две находки
ревью безопасности: потолок факта выводит прозрачность из `is_production` участка, а не
из присланного `qty_passthrough`; отгрузка берёт advisory-блокировку по позиции (две
параллельные попытки не превысят выпущенное). И `20261005092736_erp_clamp_trusted_state`: исключение
из потолка — только если этап прозрачен и до, и после правки; потолок проверяется при росте
числа, выходе из `skipped`, смене цеха и вставке с фактом (проба с откатом: «skipped + 999»
отклонён, обычная сдача 70 проходит, 71 — нет, закупка без потолка). Инструмент применения держит на скрытом
подтверждении текст с `drop trigger`/`disable trigger` — первая проба упала по таймауту;
переписано на `create or replace trigger` и разметку до триггера.

### Решения агентов, о которых стоит знать

- «Заказано поставщику» больше не копирует «Нужно по заказу» в форме закупки.
- Маркировка — во вкладке «Готовые изделия».
- Замер при завершении рулона пишется корректировкой `length_refine`, а не
  `leftover_measure`; точная атомарная операция потребует RPC `erp_roll_finish`.

## Состояние на 2026-10-01 (сессия 77) — правки ERP 01.10: шесть пунктов одним PR

Ветка `claude/new-edits-01-10-hcg3zo`, PR #195. Документ владельца «правки ерп» (01.10):
шесть пунктов. Владелец: запрос о просрочке пишет системный автор «ERP»; сначала два PR,
затем — «добавь пп. 4–5 в PR 1».

### Что сделано

- **П. 1, ткань без рулонов.** Причина — данные: у 4 тканей на бою пустая единица
  (форма закупки писала `''`), их приняли без рулонов, закрой встал. Ткань без единицы
  учитывается рулонами (`materialTracksRolls` ↔ `erp_material_tracks_rolls`); закупка ткани
  без единицы пишет «кг»; `erp_material_rolls_add` добавляет рулоны к ПРИНЯТОЙ ткани без
  нового прихода (сумма весов = принятому, ключ попытки `add_key`). Закрой говорит
  «Ткань принята без разбивки по рулонам»; «Материал поступил» рулонную ткань не принимает.
- **П. 2, подсветка.** `:hover`/указатель только у `a`/`button`; заголовки склада и закупки
  ведут в заказ. Сторож в `styles.test.ts`.
- **П. 3.** «Новый заказ» и формы ввода не закрываются по затемнению и Escape
  (`Modal`: `closeOnOverlay`/`closeOnEscape`).
- **П. 6.** Файлы заказа правятся в форме правки (`EditOrderFiles`): удалить/заменить/
  загрузить сразу. DELETE-политика вложений открыта `order.manage` для файлов формы;
  `erp_tz_document_remove` снимает ТЗ (`is_current = false` у группы, история остаётся).
  Кнопки — по зеркалу политики `utils/attachmentRights.ts`. `currentVersion` больше не
  подставляет старшую версию, если текущей нет (иначе снятое ТЗ воскресало).
- **П. 4, уведомления.** Уведомление гаснет, когда сообщение показано в чате
  (`erp_chat_mark_seen` ставит `read_at`), а не по клику; открытие ленты не двигает водяную
  отметку; упоминание и ответ приходят и в режиме «Без уведомлений» (отмена решения 20.09);
  колокол — «Сообщения» (счётчик с сервера) и «Сроки»; переход догружает ленту до
  сообщения; переподключение перечитывает уведомления без дублей, звук — одна вкладка;
  настройки — `erp_user_settings` (звук по умолчанию ВКЛ).
- **П. 5, просрочка.** `erp_overdue_requests_run()` + `pg_cron` 06:00 UTC: системное
  сообщение (пустой `author_id` = «ERP») «@Иванова Марийка, заказ №… просрочен…»,
  упоминание и `chat_mention`; один раз на срок (`erp_overdue_requests`, ключ заказ × срок).
  Правка/удаление сверяют автора `is distinct from` (с `<>` пустой автор пропускал всех).

### Миграции

Применены все пять: `20261001185238_erp_fabric_rolls_add`, `20261001185758_erp_order_files_edit`
(через `alter policy`), `20261001190924_erp_chat_notify_read`, `20261001194514_erp_overdue_chat_request`,
`20261001194849_erp_chat_system_guard_revoke`. Инструмент применения миграций держит на ручном

системного сообщения админом — 42501. Проба п. 5 с откатом — 7 запросов, повтор 0,
перенос срока 1.
