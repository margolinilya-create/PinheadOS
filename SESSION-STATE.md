## Состояние на 2026-10-13 (сессия 81) — правки CRM 13.10: цена изделия и нанесений

Ветка `claude/revisions-13-10-gv6gok`. Документ владельца «правки срм» (13.10) — расчёт
цены Order Studio / «Заказов v4», не ERP. Владелец: «Почему ничего не работает» — сессия
стартовала в режиме планирования (правки запрещены); после плана — делать. Решения:
минимум вышивки — без значения (поле, 0); данные — сразу в боевую базу; тестовые SKU
`futbolka`/`hudi` — убрать.

### Что сделано

- **Корень ошибки цены**: ткани хранили `priceUSD` — $ за КГ, формула множила на метры
  (10,9 $ × 92,70 / 3,29 м/кг = 307,12 ₽/м — цифра документа). Теперь `priceRub` за единицу
  (`unit`: метр/штука), `mPerKg` — только для закупки; `priceUSD` = 0, читается лишь
  у карточек без `priceRub`.
- **Формула** (`utils/costRules.ts`): (ткань + отделка + пошив + доп. материалы + обработки)
  × (1 + накладные 70 %) × (1 + наценка группы А/Б/В по тиражу 25…10 000) × (1 + срочность
  5/10/15 дней = 15/30/50 %); нанесения, бирки, упаковка — сверху без надбавок.
  `calcTotal` = итог `calcTotalBreakdown`; `priceOrder` (v4) на той же формуле. Отделка —
  у поставщика выбранной ткани, рибана не меняется на кашкорсе; воротник поло — штука;
  `includedExtras` модели не начисляются; ткань без цены — `fabricMissing`/`fabric_not_found`.
- **Нанесения** (`utils/printRules.ts`): DTF раскладкой тиража (ступень по непрерывному
  метражу, к оплате целые метры, не помещается — блок; контроль 25×25×75 = 23 250 ₽),
  DTG таблицей + карман/молния ×1,2, вышивка за 1000 стежков по способу и тиражу
  (надбавки суммируются), шелкография — большая из «цветной»/«футер», вытравка 1,35;
  A5/A6 в v4 больше не 0 ₽.
- **Интерфейс**: срочность — выбор дней (визард, v4), разбивка цены по статьям, поиск
  тканей по модели + поставщику + ткани (`utils/materialSearch.ts`), вкладки «Ткани»/
  «Отделка» в ₽ с м/кг, редактор цен — новые таблицы (`PricingRulesTabs.jsx`), курс
  сохраняется в прайс, зоны по модели (`zonesForSku`: рукава, штанины, стороны сумки,
  капюшон по `hasHood`, карман по `hasPocket`/обработке), описание из ткани
  (`utils/skuDescription.ts`), три копии формулы (SkuEditor, SkuDetailModal, ExpressCalc)
  переведены на ядро. Прайс базы ложится поверх умолчаний (`mergePrices`).
- **База** (применено): `20261013114103_order_v4_urgent_days` (столбец),
  `20261013115331_crm_pricing_13_10_catalog` (прайс, 48 тканей, 15 отделок, 50 SKU, зоны).
  Сверка после применения: все материалы с ценой в ₽, ткань шоппера по умолчанию —
  «Зенит», журнал совпал (326 записей, md5).

### Открытые долги

- Дни срочности v4 пишет отдельный RPC `order_v4_set_urgent_days`
  (`20261013152421`, применён) сразу после `order_v4_save`: правка большой функции
  через инструмент агента невозможна — любой SQL с удалением строк ждёт ручного
  подтверждения, вызов истекал; `SUPABASE_ACCESS_TOKEN` окружения — заглушка (401).
- Какие обработки входят в пошив поло (47,46 ₽ из документа) — не названо: механизм
  `includedExtras` есть, коды у PL/RG не проставлены. Нужен список от владельца.
- Визуальные эталоны `studio-sku` (desktop/mobile) обновлены владельцем через
  `workflow_dispatch` (`update_snapshots`), коммит `0fc29f3`: цифры себестоимости
  в «Каталоге SKU» изменились по формуле 13.10.
- В «Каталоге SKU» колонка «Отд» (64 px) обрезает 0,02 до «0.0» — расширить колонку;
  правка меняет эталон `studio-sku`, нужен повторный `update_snapshots`.
- Размеры зон штанин — «согласовать с производством».
- Минимум вышивки — владелец впишет в «Цены → Вышивка».
- Карман у штанов выставлен по описанию («карманы» в тексте) — проверить.
