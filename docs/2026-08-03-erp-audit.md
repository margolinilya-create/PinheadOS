## Карта

### Роуты ERP (`src/erp/ErpApp.jsx`)

Статикой: `ErpLayout`, `ErpDashboard`, `OrdersScreen`, `DepartmentQueue`.
Ленивые: `OrderCard`, `ProductionBoard`, `AdminScreen`, `ProductionTask`,
`FabricPurchasing`, `Warehouse`, `Subcontracting`, `Experimental`, `DeptLoad`,
`PlanScreen`.

### Слой данных — корень большинства находок

Единственный источник — `useErpStore` (composition root + 14 слайсов). Все экраны
читают ОДИН массив `orders` и фильтруют его в памяти. Следствия:

* серверной пагинации нет нигде, кроме архива заказов и двух экранов склада/закупки;
* сортировка и фильтрация — клиентские, на полном наборе;
* кэша, дедупликации и отмены запросов нет — их роль играет realtime;
* любой экран платит за данные всех остальных экранов.

## Находки

### Ф2 — данные

**F1. Дубли заказов — реальные строки в БД, не баг рендера.**
5 групп по `bitrix_id`: `22222` (×4), `212112`, `213`, `213231`, `213312` (×2).
Разные UUID, одинаковые названия, созданы с интервалом 25–80 секунд.
Ключи React — `o.id`, стабильные; картезиан от PostgREST-эмбедов невозможен;
guard `saving` в форме есть, двойной клик исключён. Причина: **ничто не мешает
создать второй заказ с тем же № сделки.**

**F2. Тестовые данные в проде.** 36 заказов из 147 (26 из 76 активных).

**F3. Просрочка.** 47 из 76 активных. Разбивка: 1–7 дней — 6, 8–30 — 39, 30+ — 2,
без срока — 19. Градации в интерфейсе нет, метрика не отвечает на вопрос
«что делать сейчас».

**F4. Пустые `/plan` и `/load` — потому что данных нет.** `erp_calendar_slots` — 2
строки, `erp_tz_documents` — 0, вложений — 1. `planPercent` при `qty_planned = 0`
возвращает **100** (`utils/planCard.ts`, то же в `utils/planDay.ts`) — отсюда
«100 %» на пустой неделе.

## RLS: расхождения клиента и сервера

Стражи-триггеры **есть** и делят UPDATE по колонкам: `erp_stage_guard` (этапы),
`erp_material_guard` (материалы), `erp_calendar_guard` (план). Ниже — то, что
осталось непокрытым.

| № | Риск | Факт |
|---|---|---|
| **R1** | сервер мягче клиента | `erp_orders` UPDATE = `erp_is_member()`, стража нет. Любой сотрудник ERP может через REST изменить `title`, `customer`, `due_date`, `manager`, `status`, `shipped_*` любого заказа. Клиент гейтит это правом `order.manage` |
| **R2** | сервер мягче клиента | `erp_order_items` UPDATE = `erp_is_member()`, стража нет: `qty`, `product_type`, `notes` правит кто угодно |
| **R3** | сервер строже клиента | `erp_orders` DELETE = `is_admin()`, а кнопку «Удалить» клиент показывает при `order.manage` (`OrdersScreen.jsx:101`). Менеджер с правом, но без роли admin получит 42501 — «кнопка есть, сервер отказывает» |
| R4 | мусор | `erp_tz_assignments` (устарела, пуста) держит 4 политики и 2 неиспользуемых индекса |
| R5 | advisor | `erp_has_permission(perm text)` вызываема ролью **anon**. Правило проекта («функции без аргументов, возвращают булево о самом вызывающем») её не покрывает — у неё есть аргумент |
| R6 | advisor | Auth: защита от утёкших паролей (HaveIBeenPwned) выключена |
| R7 | advisor perf | 19 неиспользуемых индексов (уровень INFO) |

Утечки чтения нет: SELECT везде `erp_is_member()`, записи снабжения —
`erp_is_manager()`, административные — `is_admin()`.

Секретов в клиентском бандле, кроме публичного anon key, нет: только
`VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` и опциональный
`VITE_ERROR_REPORT_URL`.

**Ничего в политиках не менялось** — по договорённости это отдельное решение.

## Решения заказчика (03.08.2026)

1. **Порядок фаз:** Ф0 → Ф2 → Ф3 → Ф1′ → Ф4 → Ф5 → Ф6. Сначала то, что видно
   людям каждый день; слой данных позже — при 76 заказах он ещё не жмёт,
   а бюджет бандла уже выполнен.
2. **Навигация:** один раздел «Производство» с вкладками Доска · План · Загрузка.
   `/plan` и `/load` редиректят на вкладки, `/board` переименовывается в
   «Доска производства» — конфликт заголовков исчезает.
3. **Просрочка:** срок прошёл **И** заказ не готов к отгрузке. Готовый, но не
   отгруженный заказ ждёт логистики, а не производства. Плюс градация
   1–7 / 8–30 / 30+ дней в интерфейсе.
4. **Тестовые данные:** флаг `is_demo` + фильтр в UI, по умолчанию скрыты,
   переключатель для admin/director. Ничего не удаляется.
