## Чем ошибалась разведка

1. **«`erp_warehouse_tasks_order_idx` избыточен»** — нет. «Покрывающий»
   `erp_warehouse_tasks_order_type_idx` — ЧАСТИЧНЫЙ (`where stage_id is null
   and material_id is null`), запросы по `order_id` он не обслуживает, а у
   самого индекса 76 042 чтения. Условие частичности стоит в другой миграции,
   и разведка по тексту его не увидела. Правило: индекс снимается после
   `pg_get_indexdef` и `pg_stat_user_indexes`, а не по имени.
2. **«`realtimeSlice.test.ts` в `slices/`»** — файл лежит в `store/`; мелочь,
   но показывает, что пути из отчёта агента надо проверять `ls`.
3. Разведка насчитала «114 записей changelog» — их 106: восемь `###` были
   историей и roadmap.

## Бэклог (не начато, с причинами)

- **Резка крупных файлов**: `CreateOrderModal.jsx` (submit 345 строк →
  `useOrderSubmit`, черновик → `useOrderDraft`), `ItemBlock.jsx` (шесть
  компонентов в одном файле, без `memo`), `FabricPurchasing.AddPurchaseModal`.
  Решение владельца 26.09 — отдельными PR с опусканием ратчета.
- **Пересчёт готовности** в `ErpLayout.jsx:144-201` и `DepartmentQueue.jsx:250-273`
  на каждое изменение `orders` — сначала замер React Profiler.
- **`select('*')`** в `employeesSlice`, `notificationsSlice`, `planSlice`,
  `skuSlice`; `.select()` после `update` → `.select('id')`.
- **Нестабильные пропсы у `memo`**: `DepartmentsScreen`, `Warehouse`,
  `FabricPurchasing`, `Subcontracting`.
- **Деньги Order Studio**: 77 инлайн `toLocaleString('ru-RU')`.
- **84 индекса без чтений** — пересмотр в октябре по статистике.
- **`erp_bootstrap` с полной формой** (`moves`, `attachments`, `order.due_date`)
  вернул бы один RTT экранам подряда и разработки; сторож `bootstrapSlice.test.ts`
  скажет, когда это сделано.
- **`erp_materials`**: закупочные поля открыты любому участнику на сервере
  при закрытом правами экране — решение владельца (с 24.09).
- **Тумбы** «БОЛЬШЕ НЕТ» в ратчетных файлах — по касанию.
