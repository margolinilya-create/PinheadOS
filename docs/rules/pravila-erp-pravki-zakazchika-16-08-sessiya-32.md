# Правила ERP (правки заказчика 16.08, сессия 32)


- **Карточка заказа — СТРАНИЦА, боковой панели нет.** Открывается только через
  примитив `components/OrderLink` (или `utils/orderLink.orderLinkTarget` там,
  где ссылки нет: клик по карточке канбана, Enter/Space, KPI-плитка). Он же
  несёт `location.state.from` — формат обязан совпадать с ключом
  `useScrollRestore` (`pathname + search`), иначе позиция прокрутки молча
  не восстановится. `page`/`size` списка заказов теперь В АДРЕСЕ: прежнее
  решение «страница 3 смысла не несёт» было верным ровно до тех пор, пока
  боковая панель оставляла список смонтированным
- **Упаковка живёт на ДВУХ уровнях, и правило разрешения одно** —
  `utils/packaging.itemPackaging` («своё у позиции → общее по заказу»), тем же
  приёмом, что `utils/tz.itemTzDocument`. Значение `inherit` стоит по умолчанию
  осознанно: пустое было бы неотличимо от `none` («эту позицию не упаковывать»),
  и забытая позиция уехала бы в отгрузку без упаковки
- **Размеры хранятся КЛЮЧАМИ JSON в `size_grid`**, и всё, что их показывает,
  берёт ключи из данных, а не из `SIZE_PRESETS`. Поэтому пресет можно менять
  (`XXL` → `2XL`) без миграции: старые сетки читаются как раньше, а размер вне
  пресета `SizeGridEditor` дописывает сам
- **Лист закупки формирует МЕНЕДЖЕР при создании заказа.** Секция `materials`
  в `erp_create_order` существовала всегда, но клиент слал `[]` — и закупщик
  заводил те же строки заново у себя. Поля менеджера и закупщика разделены
  и в схеме (`manager_note` рядом с `notes`, `qty_ordered`/`ordered_on` рядом
  с `qty_expected`/`qty_received`), и в таблице закупки двумя группами колонок.
  «План прихода» менеджер НЕ заполняет — он его не знает
- **Поле, подписанное звёздочкой, обязано проверяться в `validateOrderForm`.**
  Лист закупки не проверялся ВООБЩЕ: функция принимала форму и позиции, а лист
  жил отдельным состоянием — и заказ уезжал со строкой без количества. Молча,
  потому что `supply.missingPlan` требует `qty_expected`, и такая закупка
  не закроется автоматически никогда. Тост для этого не годится (правило волны
  UX-4): только из `validateOrderForm` работают рамка, `aria-invalid`,
  автоскролл и раскрытие секции. Совсем пустая строка ошибкой не считается —
  её отбрасывает сам сабмит (`isPurchaseRowEmpty`)
- **Печатная форма — `window.print()`, без PDF-библиотеки** (решение заказчика).
  Она НЕ сохраняет файл в документы заказа: это отдельное решение. Не выдавать
  печатную страницу за выполненный пункт «PDF хранится рядом с ТЗ»
