# Правила ERP (снятые отступления, 21.08)


- **Финальный шаг «Склад» в маршруте ВЫЧИСЛЯЕТСЯ** (`utils/warehouseStep`),
  этапом не заводится: непроизводственный цех не попал бы ни в очередь,
  ни на канбан (дефект 12.08 с 33 заказами). Состояние читается из задач
  склада ЗАКАЗА — упаковка и отгрузка идут по заказу целиком. «Нет задач»
  означает «ждёт производство», а не «готово»: их заводят триггеры по мере
  закрытия цехов. Приёмка материалов и приёмка подряда в шаг не входят —
  первая идёт до производства, вторая внутри маршрута
- **Перенос модели в каталог SKU — форма сверки, а не кнопка**
  (`utils/skuFromDev` + `screens/experimental/DevToSku`). Пакет описывает
  модель словами технолога, каталог — артикул числами прайса: код, категория,
  цена пошива и расход ткани из пакета НЕ выводятся. Перенос «одной кнопкой»
  завёл бы артикул с нулевой ценой — визард ломается на таком молча, а чинит
  не тот, кто переносил. Ненайденные в справочнике ткани показываются,
  а не отбрасываются: пропавшая ткань превращает «шьём из трёх» в «шьём
  из двух»
- **Каталог пишет ОДИН оператор внутри `erp_sku_from_dev`.** `sku_catalog` —
  одна строка `app_config`, и клиентское «прочитать → дописать → записать»
  оставляет окно, в котором редактор SKU затирает новый артикул молча.
  Функция `security definer` осознанно: RLS `app_config` пускает только
  admin/director, а `catalog.edit` есть и у руководителя производства —
  `invoker` дал бы «кнопка есть, действие падает»
- **Повторный перенос запрещён** (`erp_experimental.sku_code`): второй артикул
  той же модели — два источника правды о ней, и заказы разойдутся по обоим.
  Переносится только разработка, готовая к серии: иначе гейт полноты пакета
  обходится с другой стороны
