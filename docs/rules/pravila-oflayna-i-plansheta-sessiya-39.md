# Правила офлайна и планшета (сессия 39)


- **Офлайн-ОТКРЫТИЕ ≠ офлайн-работа, и говорить надо второе.** `public/sw.js`
  кеширует КОД (оболочку и `/assets`, `/fonts`), данные живут в Supabase —
  открытое без сети приложение покажет пустые экраны и полосу «связь
  потеряна». Ответы Supabase не кешируются сознательно: выборка зависит
  от вошедшего, а планшет в цеху общий — это ровно тот дефект, против
  которого написаны `resetErpStore()` и `storageClearAll()`
- **`skipWaiting()` в service worker запрещён.** Он ставит новый worker под
  УЖЕ ОТКРЫТУЮ вкладку, которая работает со старыми именами чанков: первый
  же ленивый экран запросит файл прошлой выкладки. Это своими руками
  воспроизведённая поломка, которую лечит `lib/appUpdate`, причём без всякой
  выкатки. Сторожит `lib/serviceWorker.test.ts`, читая текст `sw.js`
- **`unregister()` НЕ отбирает управление у открытой страницы.** Аварийный
  выключатель `?sw=off` сначала не работал именно поэтому: регистрация
  снималась, а worker продолжал обслуживать ассеты страницы и заводил кеш
  заново поверх стёртого. Решение — проверять КЛИЕНТА (`event.clientId` →
  `clients.get`): страница, открытая с `?sw=off`, обслуживается мимо кеша
  целиком. Выключатель обязателен: до парка цеховых планшетов руками
  не дотянуться
- **`reuseExistingServer` для `vite preview` запрещён** (в отличие от dev).
  Dev подхватывает правки сам, preview раздаёт папку, собранную один раз, —
  оставшийся с прошлого раза сервер прогонял бы спеки против ПРЕЖНЕГО кода.
  Своя папка `dist-e2e`: `dist` читает `bundle:budget`
- **Экран с таблицей обязан иметь компактную раскладку — ВСЕ экраны.** После
  22.08 приём был у очереди, доски, списка заказов, склада и закупки; 23.08
  добавлены подряд, загрузка цехов, ЭКС, сотрудники и участки. «Загрузка» —
  не список, а матрица «цех × 7 дней»: карточка на ЦЕХ с лентой недели внутри,
  а не на строку
- **Открытие карточки на планшете — отдельная КНОПКА, а не касание карточки.**
  Палец задевает её при прокрутке, и «переход по касанию» уводил бы с экрана
  без спроса. У строки таблицы этой беды нет — там курсор
- **Плановая дата этапа появляется ТОЛЬКО при взятии в работу**, то есть
  у этапа, который уже запущен. Этапы `waiting` — то будущее, ради которого
  заведена «Загрузка цехов», — не получают её никогда по построению: на проде
  22.08 даты были у 16 этапов, и все шестнадцать `done`. Пока `planned = 0`,
  экран говорит это прямо (`buildDeptLoad().totals`), а не рисует семь
  колонок прочерков: строки цехов есть — их держат этапы без плана, — поэтому
  пустое состояние не показывается вовсе, и экран выглядит рабочим, отвечая
  неправду
