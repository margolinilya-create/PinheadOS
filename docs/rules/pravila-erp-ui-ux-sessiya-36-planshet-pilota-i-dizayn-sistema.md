# Правила ERP (UI/UX, сессия 36 — планшет пилота и дизайн-система)


- **Экран с таблицей обязан иметь компактную раскладку.** `useCompactLayout()`
  (`<1024px` или `pointer: coarse`) + карточки вместо строк, вид — семейство
  `.dataCard*` (`.orderCardM*` теперь `composes` его). До 22.08 приём был
  у очереди цеха, доски и списка заказов и БОЛЬШЕ НИГДЕ: «Склад» рисовал
  на планшете таблицу из шести колонок, «Закупка» — из четырнадцати, и колонка
  «Действие» стоит последней — кнопка, ради которой на экран и приходят,
  уезжала за край у людей, ради которых пилот и запущен
- **Комментарий, объясняющий отсутствие покрытия, обязан описывать факт.**
  `playwright.config.ts` исключал `erp-warehouse.spec.ts` из проекта `mobile`
  словами «ниже 1024px экран показывает карточки». Карточек не существовало
  ни одной: исключение выглядело обоснованным, а покрытия не было ни на одной
  ширине. Такой комментарий хуже отсутствующего — он закрывает вопрос
- **Содержимое ячеек, которое показывают обе раскладки, живёт в ОДНОМ модуле**
  (`purchasing/PurchaseFields`). Поля закупки — не подписи, а инлайн-правки
  со своим условием записи («пиши, только если значение изменилось»), и вторая
  копия под карточку разошлась бы молча: обе «работают», просто пишут по-разному
- **Подписи полей в карточке ставятся ЯВНО**: вместе с шапкой таблицы исчезают
  названия колонок, и «110» без слова «Заказано» ничего не значит. Группы
  колонок («Потребность — задал менеджер» / «Факт — ведёт закупка») переживают
  смену раскладки двумя подписанными блоками
- **Прежде чем заводить класс — проверьте примитив.** Главное действие карточки
  это `Button block`: ширину и ≥44px на тач-экранах он уже даёт. Свой класс был
  заведён и удалён в той же сессии
- **Фолбэк `var(--token, X)` запрещён, и это ПРОВЕРЯЕТСЯ** —
  `src/styles/tokens.test.ts`. Правило жило в CLAUDE.md с волны UX-4 без
  сторожа, фолбэков накопилось девяносто, и часть уже разошлась со значениями
  (`--color-success, #34c759` при реальном `#06a77d`; `--text-muted, #888` —
  ровно то значение, которое аудит контраста забраковал за 2.81:1)
- **Необъявленный токен без фолбэка делает объявление невалидным, и браузер
  отбрасывает его МОЛЧА.** Тот же сторож требует, чтобы каждый `var()` ссылался
  на объявленный токен, и нашёл три живых случая: `var(--border-str)` —
  наведение не меняло рамку, `var(--type-sm)` — размер шрифта не задавался,
  `var(--bg-card, …)` — фон держался на фолбэке. Ни один тест такого не видит:
  CSS собирается, экран рисуется, просто не так, как написано
- **Ink-токены делятся на две работы при общем суффиксе.** `info/violet/cyan-ink`
  — цвет ТЕКСТА на плашке `--bg-*` (чипы), в тёмной теме осветляются;
  `success/error/warning-ink` — ЗАЛИВКА под белым текстом (тост, danger),
  в тёмной теме остаются тёмными. Оба семейства объявлены в `index.css`:
  чипы живут и в админке, смонтированной вне `.shell`
- **Палитра `.shell` проверяется контрастом машиной.** `contrast.test.ts` читал
  только `index.css`, а раздел «Производство» работает на 37 (светлая) и 34
  (тёмная) переопределённых токенах — единственной проверкой был комментарий
  в CSS. Теперь тест читает оба источника: 12 пар «заливка чипа × чернила»
- **Тема идёт за системой, пока человек не выбрал сам** (`prefers-color-scheme`
  не встречался в проекте ни разу при обещании DESIGN.md «автоматически»).
  Запись в localStorage — ТОЛЬКО из тумблера: запись из эффекта сохранила бы
  вычисленное значение при первой отрисовке, и «авто» стало бы «как было
  в день первого визита»
- **`prefers-reduced-motion` перечисляет классы адресно**, без `!important`:
  он в проекте запрещён, а правило-звёздочка без него не работает. Список
  ведётся как список ≥44px — добавили движение, впишите класс туда же
- **CSS раздела едет с разделом.** `styles/index.css` держит только всегда
  нужное (layout · forms-buttons · auth · utils); шесть файлов Order Studio
  импортируют потребители (`OrderStudioApp` и ленивая `AdminPanel`). Раздел
  стоит за выключенным флагом, а его 128 кБ сырого CSS ехали каждому, кто
  открыл только «Производство», — оболочка ERP не использует оттуда ни одного
  класса. CSS оболочки 36,7 → 22,1 кБ gzip, потолок бюджета снижен до 24 кБ
- **Три состояния экрана — не «в основном соблюдается».** Сверка нашла: «Склад»
  без скелетона (пустая страница при загрузке неотличима от «задач нет»),
  «Сотрудники» и «Участки» без `loadError` вовсе. У `loadEmployees` сбой
  не поднимал `employeesLoaded`, а эффект второй раз не срабатывает — экран
  оставался пустым НАВСЕГДА, выходом была только перезагрузка

- **Разнося CSS по чанкам, проверьте каждое правило, которое выигрывало
  ПОРЯДКОМ.** `utils.css` был десятым из десяти в `styles/index.css`, и его
  секция RESPONSIVE переопределяла базовые правила ТОЙ ЖЕ специфичности —
  «последнее слово» доставалось ей бесплатно. Когда стили Order Studio уехали
  в свой чанк, `utils.css` остался глобальным и стал первым: мобильные правила
  молча перестали применяться. Функциональные тесты такого не видят —
  разметка и поведение те же, отличается вид; поймал ОДИН visual-эталон.
  Пока файл один, порядок бесплатен; как только их два, он перестаёт
  существовать как понятие
- **Адаптив живёт рядом со своим разделом** (`styles/responsive.css`,
  импортируется ПОСЛЕДНИМ у `OrderStudioApp` и `AdminPanel`), а не в общем
  «разном». Внутри чанка порядок мы контролируем — значит правило выражается
  порядком
- **Защитному минимуму, который нужен ВСЕМ разделам, порядка не хватает.**
  Правило «поля ≥16px против зума iOS» живёт глобально (форма входа, ERP,
  Order Studio), то есть «последнего места» у него нет вовсе. Приоритет
  выражен специфичностью — `html` перед селектором: один лишний элемент
  побеждает случайные совпадения (`.sku-ed-rate-internal input`) и НЕ
  побеждает осознанные переопределения с двумя классами
  (`input[type="number"].pe-usd-input`). `!important` запрещён и не нужен
- **`prefers-reduced-motion` на весь проект УЖЕ ЕСТЬ** — общий `*`-блок
  в `utils.css`, единственное задокументированное исключение из запрета
  `!important`. Прежде чем добавлять свой блок для раздела, проверьте, что
  существующий его не покрывает
