## Решения К1–К16 коротко

- **К1. История — `history[]` в записи флэта.** `{ version, views }` прежних версий как есть,
  с путями своей версии. Одна запись `catalog_put` атомарно выпускает версию и сохраняет прежнюю
  геометрию. Размер меряется как на сервере — байты UTF-8 (`catalogBytes`), предупреждение
  с 80 % от 1 МБ, отказ — до загрузки файлов.
- **К2. Выпуск только геометрии переносит файлы всех видов** на `v<N+1>`: свежий
  `downloadFlatSvg` → `resolveFlat` → `uploadFlatSvgOnce`. Кэш холста для переноса не
  используется (он кэширует неудачу). Сбой переноса — `files`, справочник не тронут.
- **К3. «Уже есть» сверяется содержимым** (`uploadFlatSvgOnce` → `'uploaded' | 'same' | 'differs'`):
  `'differs'` — следующая версия и все виды заново, не больше 5 попыток (только на гонку двух
  администраторов). Требует идемпотентного санитайзера (тест на 67 SVG сида, зеркале, `flat-evil.svg`).
- **К4. Файлы попадают в бакет при сохранении**, не при выборе: DELETE нет, загрузка при выборе
  оставляла бы сирот. До `catalog_put` на файл никто не ссылается — смысл правила «файл, видимый
  приложенным, обязан быть в бакете» соблюдён.
- **К5. DELETE версий — не в 5б.** Политики DELETE у `garment-flats` нет и не будет без отдельного
  решения; уборка ничьих версий — бэклог (возраст + проверка ссылок на сервере).
- **К6. Правило версии** — ниже.
- **К7. Одна правка — один флэт**, конфликт — правило вехи 4 (P0001, плашка, «Загрузить свежую
  версию», без автослияния).
- **К8. `tz_row` — код из перечня** (`TZ_ROW_CODES`: 9 строк матрицы + `other`); цепочка
  `area.tz_row` → `zone.tz_row` → `DEFAULT_TZ_ROW_BY_ZONE` → `other`. Справочник зон правится
  только во «Флэтах и зонах»; `/sku` → «Зоны нанесения» — просмотр со ссылкой.
- **К9. Загрузка SVG — WYSIWYG через санитайзер**: принимается очищенный файл, «Из файла убрано»
  показывается списком по виду (≤ 20 строк); нет `<g id="garment">` или `viewBox` — отказ.
- **К10. Рукава** — загрузка вручную и «Сделать правый рукав зеркально» с ОТРАЖЁННЫМ SVG
  (`<g transform="matrix(-1 0 0 1 …)">`), якоря, зоны и знак x-дельт ростовки зеркалятся.
- **К11. Калибровка** по известному размеру умножает ВСЕ позиции вида на `k` (зоны и якоря остаются
  на тех же точках силуэта); физические величины (`safe_inset_mm`, лимиты печати) не меняются.
  Калибровка — геометрия, значит новая версия.
- **К12. Зоны-многоугольники** правятся точками; в прямоугольник — только по кнопке. «Логотип в зоне»
  на холсте 5а по-прежнему проверяется по описывающему прямоугольнику (бэклог).
- **К13. Ростовка и DXF — не в 5б**: поля хранятся как есть, калибровка и зеркало их не портят.
- **К14. Где код**: чистое ядро `design/edit/` (без React, `api/`, стора, тостов — сторож
  `designGuards`), писатель `admin/flats/saveFlat.ts`, его чистые части — `design/catalog/flatVersion.ts`.
- **К15. Холст рабочего места** — рукава (`DESIGN_VIEWS` = 4 вида) и геометрия по версии позиции
  (`itemFlatVersion` → `flatAtVersion`); перенос на новую версию — только кнопкой и только в черновике.
- **К16. `SALES_CLIENT_REV` не поднимается**: флаг `orderStudio` людям не включён; клиент 5а
  историю отбрасывает при разборе, но справочник флэтов не пишет (сид дописывает сырые записи).

## Геометрия → новая версия, метаданные — нет

- Классификация полей — исчерпывающая: `GEOMETRY_KEYS` и `META_KEYS` в `design/catalog/flatVersion.ts`
  для флэта, вида, якорей и зоны. Сторож сверяет их с ключами zod-схем: **новое поле без
  классификации — красный тест**, а не тихие «метаданные».
- Геометрия: набор видов, SVG вида, `scale_mm_per_unit`, якоря (и `axes`, `size_anchors`,
  `grade_rule`), набор зон и их `id`, `polygon_mm`, `safe_inset_mm`, `zone_id`.
- Метаданные: `name`, `garment_type`, `typical`, `active`, `sku_codes`, `categories`, `fits`,
  размеры; у зоны — `name`, `tz_row`, `methods`, `default_method`, `max/min_print_mm`.
- Кнопка называет результат: «Сохранить флэт» / «Выпустить версию N+1» / «Создать флэт»;
  «Отменить правки силуэта» (`revertGeometry`) возвращает геометрию базы, метаданные остаются.

## Читатели старой версии — `flatAtVersion`

- `flatAtVersion(flat, V)`: виды — из истории версии V, метаданные флэта — текущие, метаданные
  зоны накладываются из текущей версии по `area.id`; **поле `version` результата = V**.
  Иначе перетаскивание или новое размещение на позиции v1 записало бы `flat_version` текущей
  с координатами v1 — тихий переезд без `remapToFlat`.
- Во все места размещения (`PlaceCtx.flat`, `newPlacedPrint`, перетаскивание, превью, PDF,
  preflight) идёт РАЗРЕШЁННЫЙ флэт. Несколько версий у позиции или версии нет в истории — текущая
  с пометкой `stale`, как в 5а.
- Открытие вкладки ничего не пишет; «Перенести на версию M» — `remapToFlat` через `edit`, только
  в черновике. Правка `tz_row` у текущей версии меняет строку ТЗ и у черновиков на старой версии;
  выпущенный PDF — неизменяемый снимок.

## `zonesCatalog` — один писатель, название зоны неизменно

- Пишет только `admin/flats/ZonesCatalogEditor.jsx` через `useCatalogEditor('app_config',
  'zonesCatalog')` (сторож `zonesWrites.test.ts`); запись из `useSkuSave` убрана.
- Зона снимается `active: false` (не предлагается новым позициям; в старых заказах остаётся,
  `PrintRow` метит «(снята)»), не удаляется. id — `ZONE_ID_RE` (`catalog/tzRows.ts`, тот же
  исходник регулярки в SQL I — сторож `catalogKeys`).
- **Название зоны после сохранения не меняется** — оно ключ нанесения в заказах (`SalesPrint.zone`,
  цена DTG ищет «карман» в названии). Опечатку исправляют снятием зоны и новой зоной. То же —
  **имя служебной зоны флэта** (`zone_id = null`): после сохранения только для чтения.
  Устойчивый ключ `order_item_prints.zone_id` — веха 6.
- `ph_zones` больше не читается (запасной путь — `ZONES_CATALOG_DEFAULT`), ключ остаётся
  в списке очистки при выходе.

## Сохранение флэта: файлы до справочника

- Порядок `saveFlat`: без сети — `releaseFlat`, `historyPreserved`, `mergeFlatIntoRaw` (прочие записи
  СЫРЫМИ, как есть), размер, `validateFlat`, проверка склеенного справочника (битая чужая запись —
  текст с её id, запрос не шлётся) → занятые номера в бакете (`listFlatVersions`) → тексты всех видов
  → загрузка → **последним** `putCatalog` с базой от свежего чтения. Отказ 22023 — вид `invalid`
  с текстом сервера дословно.
- **Стартовая версия = max(версия по справочнику и истории, наибольшая занятая `v<N>` в бакете) + 1**
  (`list` — чтение). Без этого сироты сорвавшихся сохранений и чужие объекты навсегда закрыли бы
  выпуск версий (DELETE нет). Номер версии только растёт; пропуски допустимы.
- После успеха справочник холста сбрасывается событием окна `FLATS_SAVED_EVENT` (редактор не
  импортирует `useFlatsCatalog` — бюджет холста).
- Битая запись открывается терпимо (`broken` → «Открыть для исправления») и чинится обычной правкой.

## Страж `app_config_order_catalog_guard` (миграция I)

- BEFORE INSERT/UPDATE/DELETE на `app_config`, только ключи `garmentFlats` и `zonesCatalog`,
  `security definer`. Держит то же, что клиент, и при ПРЯМОЙ записи мимо RPC: форма
  (`catalog_value_check`), флэт и зона не исчезают (снимают `active: false`), версия флэта не
  понижается, **записи истории неизменяемы — точное равенство jsonb, не `@>`** (containment
  частичный и пропускал дописанный вид), при выпуске прежние виды попадают в историю без изменений,
  название зоны неизменно.
- **DELETE строк этих ключей — только `service_role`** или владелец в SQL Editor (`session_user =
  postgres` без JWT клиента). `current_user` в `security definer` для этого не годится.
- `catalog_put`, политики, Storage и `erp_*` миграция I не трогает; md5 `prosrc` `catalog_put`
  после применения — тот же, что у H.

## L1 плана 5а отменён решением К5 (18.10)

План 5а (раздел «Проверка плана», L1) обещал «в 5б — delete только неупомянутых версий».
**Это отменено.** Политики DELETE у `garment-flats` нет, RPC «версия не упомянута» не заводится:
старые версии нужны заказам (`layout.flat_version`), PDF и вехе 6; открытые вкладки держат
справочник до 10 минут. Уборка ничьих версий — бэклог с возрастным гейтом и проверкой ссылок
(`history`, `layout`, `order_items.flat_id`) на сервере. Не заводить DELETE «по плану 5а».

## Выкатка I и окно совместимости

- Порядок: **H (вместе с выкладкой 5а) → I.** Каждый файл выкатки начинается с предусловия:
  H в `schema_migrations`, бакет `garment-flats` есть, md5 `prosrc` `catalog_value_check` и
  `catalog_put` = тела H — иначе `raise exception`.
- I — **в тот же день, что и мердж 5б**; между применением I и мерджем зоны в `/sku` не правим:
  старый редактор жёстко удаляет зоны и не проверяет уникальность названий — страж и форма
  отклонят (22023).
- Откат — вместе с фронтом и ПЕРВЫМ: снять стража, вернуть `catalog_value_check` текстом H.
  Данные `history`/`tz_row`/`active` откату не мешают. После отката снятые зоны старый фронт снова
  предложит в подборе — до повторной выкладки зоны не снимать или вернуть `active` вручную.

## Экран и бюджет

- Адрес: `?tab=flats&flat=<id>&view=<вид>`, `?tab=flats&flat=new`, `?tab=flats&part=zones`;
  смена вкладки снимает `flat`/`view`/`part`; `leaveGuard` при несохранённом.
- Правят admin и director; rop — просмотр (`fieldset disabled`, холст `readOnly`); ≤ 760 px —
  `FlatPreview` картинкой `<img>`, без konva и без правки.
- В `admin/flats/**` нет `/erp/`, `innerHTML`, иконочных кнопок без `aria-label` (сторожа
  `flatsAdminGuards`, `canvas/canvasGuards`); konva — только через `design/ui/konva` и только в ленивом
  `FlatEditor`; свои иконки `flatIcons` (не `DesignIcon` — общий модуль увёл бы иконки из чанка холста).
- Палитра холста редактора `--flat-*` — литералы светлых значений: тёмная `.shell` перекрашивает
  общие токены, бумага холста светлая в обеих темах. Исключение из правила «литерал, равный токену»;
  сторож контраста учитывает каскад `.shell`. Веха 8 — инвариантные токены `--canvas-paper-*`.
- **Бюджет:** konva не в графе `OrderSettings`, `FlatsTab`, `FlatPreview` (`bundle:budget`);
  редактор флэта ≤ 53 200 Б gzip (на 18.10 — 48 343); холст «Дизайн» ≤ 100 000 (99 890 — запас 110 Б),
  кэши картинок ≤ 9 400 (9 118); вход и оболочка ERP — побайтно как в базе. Общий с редактором модуль
  в чанке холста выводит его за потолок: новое общее — своим модулем у редактора (как `flatIcons`,
  `garmentFlatsRead`, `FLATS_SAVED_EVENT`), а не `manualChunks` (тот затягивал зависимости входа).
