# AI-инструментарий проекта

Что подключено к Claude Code в этом репозитории и что ставится отдельно на машину
разработчика. Источник — подборка из четырёх репозиториев (08.09.2026).

Разделение простое и важное: **в git живёт конфигурация, на машине — программы.**
Всё из первых двух разделов приезжает вместе с `git pull` и работает у всей команды.
Всё из третьего каждый ставит себе сам — это отдельные процессы со своими портами,
Docker-образами и ключами, репозиторием они не раздаются.

---

## 1. Каталог плагинов Anthropic

`anthropics/claude-plugins-official` — 291 плагин. Подключён как маркетплейс
в `.claude/settings.json`; посмотреть весь список и поставить ещё —
`/plugin` в Claude Code.

Включены девять:

| Плагин | Что даёт |
|---|---|
| `supabase` | MCP-сервер Supabase: БД, auth, storage, realtime |
| `playwright` | MCP-сервер Playwright: браузер под управлением агента |
| `vercel` | MCP-сервер Vercel: деплои, логи сборки, домены |
| `github` | MCP-сервер GitHub: PR, issues, ревью, поиск по коду |
| `frontend-design` | Скилл проектирования интерфейсов |
| `code-review` | Ревью PR несколькими агентами с оценкой уверенности |
| `code-simplifier` | Упрощение кода без смены поведения |
| `security-guidance` | Предупреждения на правках + ревью диффа |
| `semgrep` | Статический поиск уязвимостей по мере написания кода |

Два пересечения названы вслух — оба безобидны, но знать про них надо:

- **Четыре плагина — это MCP-серверы, и ровно они уже подключены в Claude Code
  на claude.ai** (веб-сессии). Там они задвоятся: инструменты не столкнутся
  (сервер даёт им свой префикс), но список станет длиннее. Смысл держать их
  в репозитории — локальные запуски: разработчик клонирует проект и получает
  supabase/playwright/vercel/github без ручной настройки.
- **`frontend-design` уже лежит копией в `.claude/skills/frontend-design`**
  (симлинк на набор из `anthropics/claude-code`). Плагин даёт тот же скилл.
  Дубль безвреден, но локальную копию можно снять, если решим держать
  единственный источник.

## 2. Скиллы из `vercel-labs/agent-skills`

Ставились через `npx skills` (`vercel-labs/skills` — CLI, а не набор скиллов;
устанавливать его никуда не нужно, он вызывается через `npx`). Файлы скопированы
в `.claude/skills/`, версии зафиксированы в `skills-lock.json`.

| Скилл | Зачем в Pinhead |
|---|---|
| `web-design-guidelines` | Ревью интерфейса и доступности — рядом с нашими правилами про контраст и WCAG |
| `vercel-composition-patterns` | Композиция React-компонентов, включая изменения API React 19 |
| `vercel-react-best-practices` | Производительность React |
| `vercel-react-view-transitions` | View Transition API — анимации переходов |
| `deploy-to-vercel` | Деплой |
| `vercel-cli-with-tokens` | Vercel CLI по токену, без интерактивного логина |
| `vercel-optimize` | Стоимость и производительность на Vercel |
| `writing-guidelines` | Ревью прозы документации |

Девятый скилл набора, `vercel-react-native-skills`, **не ставился**: React Native
в проекте нет, а описание каждого скилла грузится в контекст каждой сессии.

Обновить или добавить:

```bash
npx skills add vercel-labs/agent-skills --agent claude-code --copy --list   # посмотреть
npx skills add vercel-labs/agent-skills --agent claude-code --copy --skill <имя>
```

`--copy` обязателен: без него CLI кладёт симлинки, и в git уедет ссылка вместо файлов.

## 3. Отдельные программы (ставятся на машину, не в репозиторий)

### Strix — AI-пентестер

`usestrix/strix`, Apache-2.0. Гоняет агентов против приложения и ищет уязвимости.
Нужен **Docker** и **ключ LLM-провайдера**; результаты пишутся в `strix_runs/<run-name>`.

```bash
curl -sSL https://strix.ai/install | bash

export STRIX_LLM="openrouter/z-ai/glm-5.3"   # или другой провайдер
export LLM_API_KEY="..."

strix --target ./pinhead-react
```

Готовый скрипт с проверками — `scripts/install-ai-tools.sh strix`.

Две вещи про запуск:

- Первый прогон тянет Docker-образ песочницы — это несколько минут и заметный
  объём диска.
- **Натравливать только на свой стенд.** Инструмент атакующий: скан чужого хоста
  без письменного разрешения владельца — это не тестирование, а взлом. Для Pinhead
  это означает локальный `npm run dev` или отдельный превью-деплой, но не прод
  с боевыми заказами: агент отправляет реальные запросы и может создавать
  и портить данные.
- `strix_runs/` добавлен в `.gitignore` — отчёты содержат выдержки из кода
  и найденные уязвимости, им не место в репозитории.

### OmniRoute — AI-шлюз

`diegosouzapw/OmniRoute`, MIT. Один OpenAI-совместимый endpoint поверх множества
провайдеров, с автопереключением при исчерпании квоты.

```bash
npm install -g omniroute
omniroute
# дашборд http://localhost:20128 · API http://localhost:20128/v1
```

Docker-вариант и настройка под конкретные CLI — в `docs/guides/SETUP_GUIDE.md`
и `docs/reference/CLI-TOOLS.md` самого репозитория OmniRoute.
Скрипт — `scripts/install-ai-tools.sh omniroute`.

**Прежде чем направлять в него работу по Pinhead, решите вопрос про данные.**
Шлюз стоит между инструментом и моделью, то есть через него идёт содержимое
запросов: исходники, схема БД, куски заказов, попавшие в отладочный вывод.
Дальше они уходят тому провайдеру, которого выбрал роутер, — а «бесплатные»
провайдеры обычно бесплатны потому, что оставляют за собой право учиться
на трафике. Pinhead — закрытая ERP с данными клиентов типографии, и это
не то же самое, что личный пет-проект.

Практический вывод: держать его для экспериментов и открытого кода, а на боевом
коде — либо не использовать, либо ограничить список провайдеров теми, с кем есть
соглашение о неиспользовании данных. Ключи провайдеров живут в дашборде
OmniRoute, в `.env` проекта им не место.

## Что и где лежит

| Путь | Что это |
|---|---|
| `.claude/settings.json` | Маркетплейсы (`extraKnownMarketplaces`) и включённые плагины (`enabledPlugins`) |
| `.claude/skills/` | Скиллы проекта, в том числе восемь новых от Vercel |
| `skills-lock.json` | Зафиксированные версии скиллов, поставленных через `npx skills` |
| `scripts/install-ai-tools.sh` | Установка Strix и OmniRoute на машину разработчика |
