## Состояние на 2026-07-22 (сессия 22) — QA-баг-репорт заказчика: 16 багов ERP

**Замысел:** заказчик прислал QA-репорт (16 багов основного ERP, Order Studio исключён). Разведка —
2 Explore-агента (логика/даты + счётчики/бейджи), фиксы по кластерам. Ветка перезапущена от main.

**Критичные/логические (данные):**
- **ERP-01/02** (Закупка) — `statusGroup` в `FabricPurchasing`: статус приоритетнее `eta`. Строка
  «Заказано/В пути/Пришло» больше не зависает в «Просрочено»; KPI-плитки и фильтр-вкладка
  пересчитываются. «Просрочено» = только не заказанная закупка с истёкшим eta.
- **ERP-03** — `DueCell`: завершённый заказ (есть `shipped_at`/`delivered_at`) показывает срок без
  «просрочен NN дн.» (лейбл «сдан вовремя/заранее» — в статус-колонке).
- **ERP-04** — `QueueCard`: план завершения этапа по умолчанию = срок клиента, а не «сегодня» —
  этап с дальним сроком не помечается «просрочен» на след. день. (Сам `stageOverdue` был корректен.)

**Счётчики/бейджи:**
- **ERP-05** — бейдж колонки канбана = все видимые карточки (ready+blocked+in_progress+done).
- **ERP-06** — новый `readyOnlyCountFor` (только ready, без in_progress) для бейджа вкладки цеха и
  «Мой цех»: убывает при «Взять в работу», совпадает с группой «Готово к работе». `readyCountFor`
  оставлен для уведомления о новой работе.
- **ERP-07** — готовое изделие подряда стартует с «Ожидает оплаты» → попадает в степпер; степпер
  переносится по строкам (подпись последнего шага не обрезается).
- **ERP-08** — `subcontracting`/`experimental` грузятся заранее в `ErpLayout` — бейджи «Подряд»/
  «Эксперим.» стабильны на любом экране (не «пусто → 10»).
