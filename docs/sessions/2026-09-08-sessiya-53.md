### Решения

- **Из четырёх репозиториев подборки скиллы — только один набор.** Маркетплейс,
  CLI-установщик и две самостоятельные программы — разные вещи, и «установить»
  для каждой означает своё. Разделение проведено по тому, что доживает
  до машины: конфигурация в git, программы руками.
- **Strix и OmniRoute не ставились в контейнер.** Сессия эфемерная, глобальная
  установка исчезла бы вместе с ней; в репозиторий уехал скрипт с проверкой
  предусловий и подтверждением.
- **`vercel-react-native-skills` не ставился** — React Native в проекте нет,
  а описание каждого скилла занимает контекст в каждой сессии.
- **Два пересечения названы, а не спрятаны.** Четыре плагина-MCP (supabase,
  playwright, vercel, github) дублируют серверы, подключённые в веб-сессиях;
  держим ради локальных запусков. `frontend-design` дублирует одноимённую копию
  в `.claude/skills/` — при желании локальную можно снять.
- **OmniRoute отмечен как решение про данные, а не про удобство.** Через шлюз
  идёт содержимое запросов к провайдерам; Pinhead — закрытая ERP с данными
  клиентов. Рекомендация в доке: эксперименты и открытый код — да, боевой код —
  только с провайдерами, у которых есть соглашение о неиспользовании данных.
