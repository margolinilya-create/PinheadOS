## Откатить релиз (30 секунд)

Vercel → проект → Deployments → выбрать предыдущий production-деплой с
`isRollbackCandidate: true` → **Instant Rollback**.

**Важно:** откат возвращает ТОЛЬКО фронтенд. Если релиз ехал вместе с миграцией БД,
старый фронт встретит новую схему. Поэтому правило релиза: миграции только аддитивные
(новая колонка nullable, новая функция рядом со старой), удаление колонок и смена
сигнатур RPC — отдельным релизом через неделю после того, как фронт перестал их
использовать. Тогда фронт-роллбэк остаётся достаточным откатом.

## Восстановить БД

1. Supabase Dashboard → Database → Backups.
2. План Pro даёт ежедневные бэкапы с хранением 7 дней. **PITR — платный аддон**;
   на 29.07.2026 признаков его включения нет — проверьте перед тем, как обещать
   точку восстановления точнее суток.
3. Restore in place: база маленькая (147 заказов / 443 этапа), занимает 20–40 минут.
   `project_ref` и URL не меняются, фронт переподключается сам.

**Что при этом теряется:**

- **до 24 часов работы цехов**, если PITR выключен: перемещения этапов, `qty_done`,
  брак, приёмка материалов. Восстанавливается только опросом людей;
- **файлы Storage не вернутся вообще** — бэкапы Supabase покрывают Postgres, но не
  объекты Storage, версионирования у бакетов нет, а код удаляет через `remove()`
  (hard delete). ТЗ-PDF и фото моделей придётся загружать заново вручную;
- **edge-функция `domain-events-dispatcher`** — её исходника нет в репозитории,
  существует в единственном экземпляре на серверах Supabase.

## Развернуть окружение с нуля

**Состояние на 29.07.2026: восстановлено, но реальным реплеем ещё не подтверждено.**

Было: в проде 60 применённых миграций против 45 файлов в репозитории — 18 применялись
напрямую через MCP и файлов не имели. Реплей падал на
`20260727200000_erp_material_suppliers_rls`, потому что функции `erp_is_member()`
в схеме нет: во всём репозитории она только использовалась и нигде не создавалась.
Ветвление Supabase висело в `MIGRATIONS_FAILED` с 26.05.2026, то есть чек
`Supabase Preview` не проходил никогда (на PR без миграций он просто `skipped`).

Сделано:

- недостающие миграции выгружены **дословно** из `supabase_migrations.schema_migrations`
  (колонка `statements` хранит исходный SQL) и разложены файлами в порядке применения;
- добавлена `20260101000100_order_templates.sql` — таблица существовала в проде, но
  `create table` не было нигде, а `orderstudio_rls_perf` писал для неё политики;
- три легаси-файла (`20260415202746`, `20260515104159`, `20260515104329`) ссылались на
  объекты, снесённые `drop_legacy_erp_redesign_v2`, и на чистой базе падали бы с
  42P01/42883 — операции над ними обёрнуты в `to_regclass`/`exception`-guard'ы.
  Операции над пережившими объектами оставлены безусловными: без них свежее окружение
  получило бы `is_admin()` и `log_order_changes()`, вызываемые через `/rest/v1/rpc/`,
  и публичное чтение бакета `sku-photos`;
- сплошная проверка порядка по всем 53 файлам: неразрешённых ссылок на несозданные
  объекты не осталось.

**Чего ещё нет и почему нельзя обещать «работает»:**

- реплей **не запускался** — это статический анализ. Единственная реальная проверка
  сейчас это чек `Supabase Preview` на PR, трогающем миграции;
- `supabase/config.toml` в репозитории нет, CLI не инициализирован, поэтому
  `supabase db reset` / `db push` по-прежнему недоступны;
- восемь миграций `copy_*_from_shared` не переносились: это литеральные `INSERT`
  каталогов из другого Supabase-проекта (в `sku_catalog` зашиты URL фото чужого
  проекта), без `ON CONFLICT`. Их место — seed, а `npm run seed` сам устарел
  (ссылается на удалённые экспорты и пишет ключи, которых `lib/catalogs.ts` не читает);
- совпадение текста миграций не гарантирует совпадения итогового состояния схемы:
  гранты, владельцы, расширения и состав публикации `supabase_realtime` не сверялись.

## Как узнать, что сломалось

Сейчас — **никак, кроме звонка из цеха**. Сбора ошибок фронта нет (Sentry не
подключён, `ErrorBoundary` пишет `console.error` в браузер пользователя),
Vercel Web Analytics выключён, Runtime Errors пусты и будут пусты всегда:
приложение статическое, серверного рантайма нет, ошибка в React-компоненте туда
не попадает физически. Алертов нет.

Что есть: Supabase Logs (Postgres / PostgREST / Auth) — они отвечают на «упала ли
база», но не на «у раскройного цеха белый экран».
