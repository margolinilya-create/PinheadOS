## 1. Требования

**Функциональные:** расчёт → варианты → КП → оплата → ТЗ → запуск в ERP → готов; образцы и разработка как связанные заказы; задачи дизайнеру и технологу; документы из данных; библиотеки общие с ERP.

**Нефункциональные:**
| Параметр | Значение | Следствие |
|---|---|---|
| Расчётов в неделю | > 50, половина доходит до КП | ~3 000 заказов в год; индексы по автору и статусу, пагинация списка |
| Позиций в заказе | до 3, до 3 вариантов | UI без виртуализации, сетка компактная |
| Доступность | критична: продажи встают | офлайн-черновик, гейт CI, статус-страница |
| Устройства | десктоп + просмотр с телефона | карточка и список адаптивны, визард и холст — только десктоп |
| Пользователей | ~10 (продажи, сопровождение, дизайнер, технолог, РОП) | один дизайнер — общая очередь по времени |

**Ограничения:** стек PinheadOS (React 19, Zustand, Supabase, Vercel), команда — владелец + Claude Code, ERP уже в проде и не перестраивается.

## 2. Роли и видимость

| Роль | Видит | Делает |
|---|---|---|
| Менеджер продаж | Свои заказы; завершённые и шаблоны всех — в поиске | Расчёт, варианты, КП, оплата, ТЗ, задачи, копии |
| РОП | Все | + согласование цены в чате, запуск без оплаты, передача заказов между менеджерами, правила сроков и цены, аналитика по всем |
| Менеджер сопровождения | Все оплаченные и готовые к запуску | Проверка ТЗ, запуск |
| Дизайнер | Очередь задач + связанные позиции | Раскладка, макеты, подготовка к печати |
| Технолог | Очередь задач + позиции пошива/разработки | Проверка ТЗ (вернуть или править), лекала и флэты (право «редактор лекал») |
| Директор / админ | Всё | Библиотеки, пороги, шаблоны КП |

Передача заказа: менеджер может передать сам, РОП — переназначить.
Удаление: автор — черновик до КП; после КП — только архив; после запуска — только запрос отмены, который подтверждает производство.

## 3. Компоненты и потоки

```
┌──────────────── ORDER ────────────────┐      ┌──────── ERP ────────┐
│ Список заказов (канбан / таблица)      │      │                     │
│ Карточка заказа ──► Визард позиции     │      │ erp_create_order    │
│     │                 └ Дизайн-мейкер   │ мост │ производство        │
│     ├ Варианты · Цена · Срок            │─────►│ экономика (цена)    │
│     ├ КП · ТЗ · тех-лист · текст        │      │ fg_receipt → done   │
│     ├ Оплата · Запуск                   │◄─────│ статус, чат         │
│     └ Чат сделки (общий)                │      │                     │
│ Задачи · Экспресс · Аналитика · Настр.  │      │ Справочники, SKU    │
└────────────────────────────────────────┘      └─────────────────────┘
```

Библиотеки: общие — в ERP (SKU и карточки моделей с флэтами, ткани и поставщики, бланки, зоны и места, бирки, упаковка, типы изделий с признаком маркировки, Pantone); продажные — в Order (цены и конструктор цен нанесений, ставки подготовки, прайс образцов и разработки, правила сроков, пороги, тексты и шаблоны КП, производственный календарь).

## 4. Объекты и поведение

### 4.1 Заказ
Номер `PH-XXXX` · название автоматом (клиент + первая позиция), переименовать можно · тип: **тираж / образец / разработка / переделка** + связи между ними · сделка Bitrix (к запуску) · клиент и контакт текстом · менеджер · дедлайн · срок в рабочих днях по производственному календарю · доставка (способ: самовывоз / курьер / ТК, адрес) · упаковка заказа: индивидуальная, способ складывания, вложения, размер, стикеры, «без ЧЗ» (подсказка из справочника типов изделий) · срочность +20 % · скидка на заказ (% или сумма) · оплаты: список платежей (предоплата / доплата, сумма, дата), остаток · чат · история (статусы, цена, тираж, нанесения, открытие КП) · архив.

**Варианты** — два уровня, до 3: набор позиций целиком (сценарий A/B) и альтернатива внутри позиции (та же модель, другая ткань). После выбора клиентом остальные удаляются.

### 4.2 Позиция — визард 5 шагов
1. **Тип:** пошив по SKU · бланк (наш со склада или сторонний под заказ) · давальческое · разработка.
2. **Изделие:** поиск → карточки (до 4 фото + флэт, статус активный / снят / в разработке, бейдж «быстрый запуск»). SKU = модель + крой; ткань — отдельно: поставщик выбирается менеджером, у поставщика своя палитра и цена; «ткань клиента» — цена 0. Бланк: цена + скидка от тиража. Давальческое: описание, фото; в КП и ТЗ всегда оговорка о браке. Разработка: анкета (посадка, детали, ткань, референсы) + цена по сложности (простая / средняя / сложная).
3. **Сетка:** таблица цвета × размеры; цвет из палитры поставщика или «свой» с Pantone и фото; цена от размера не зависит.
4. **Нанесения:** живое превью; дизайн-мейкер встроен (кроме давальческого — там только мм). Техники: шелкография, вышивка, DTF, флекс/термоперенос, DTG, сублимация, шевроны/нашивки — набор фиксирован, цены в конструкторе. Ставка подготовки (формы, программа) — один раз на заказ. Выход за зону — предупреждение, не блок.
5. **Бирки:** составник, основная, размерник, хэнгтег, стикер на упаковку, флажок/патч; где производится — из библиотеки; режим: варианты из библиотеки или конструктор.

Плюс: обработки по категории, заметки кроя и пошива, исключение по упаковке. Наценка — по тиражу **каждой позиции**.

### 4.3 Нанесение
Техника · зона · группа размеров → мм (ширина, высота, отступ) · раскладка на цвет × группу · Pantone из справочника · эффект · на крое / на готовом · макет (обязателен перед ТЗ, ссылка на сервер + рабочая копия для холста) · «применено к ТЗ» / «изменено».

### 4.4 Образец, разработка, переделка
- **Образец** — свой заказ по прайсу образцов, оплата отдельно — решает менеджер; результат и доработка живут **в ЭКС**, Order только читает; при «утверждён» тираж создаётся автоматически.
- **Разработка** → образец → тираж; новая модель в каталог автоматически при утверждении техпакета.
- **Переделка** — новый заказ по рекламации (статус, причина, связь), цена по решению РОПа.

### 4.5 Задачи
Создаются автоматом («отдать дизайнеру») и вручную; одна очередь дизайнера, **порядок — по дедлайну заказа автоматически** (решение 27.09 после ревизии); технолог — проверка ТЗ пошива и разработки. Экран «Задачи».

### 4.6 Документы
| Документ | Особенности |
|---|---|
| КП | PDF + онлайн-ссылка (просмотр, фиксация открытия); шаблоны: короткое / подробное / тендерное; до 3 вариантов тиража и техники; детализация по выбору менеджера; условия — фиксированный текст; цена без срока действия; округление до 5 ₽ |
| ТЗ | Одно на заказ, всем цехам целиком, полностью из полей (без свободных фото-карточек) |
| Тех-лист | 1:1 из раскладки |
| Текст ТЗ | для мессенджеров |
| Счёт | не в Order (1С / Bitrix) |

### 4.7 Статусы
```
draft ─► quoted ─► [paid] + [tz_ready] (+ технолог для пошива/разработки) ─► ready_to_launch ─► production ─► done
  │ price_review (согласование в чате)                                         cancel_requested ─┘
  └ archived
```
`done` = готовая продукция принята на склад ГП в ERP; отгрузка и доплата — признаки рядом. Правки после запуска запрещены: только запрос отмены и новый заказ.

### 4.8 Цена и срок
Формула прежняя + ставка подготовки на заказ + скидка заказа; ручная цена — любая, порог по итоговой марже (% или маржа, любой) → РОП или директор согласуют в чате. Срок: система считает сумму по цепочке (закупка + пошив + нанесение) в рабочих днях по календарю и предлагает дату; в КП уходит **конкретная дата**, за неё отвечает менеджер; при поздней оплате или ТЗ — предупреждение о риске; загрузка цехов — позже. Экспресс — как сейчас, без создания заказа.

### 4.9 Уведомления
Колокол + системные браузера. Менеджеру: задача, согласование, запуск/готов, клиент открыл КП. РОПу: цена на согласование, КП без ответа N дней, готов к запуску и не запущен.

### 4.10 Аналитика
Произвольный период; воронка, время на этапах, выручка и маржа по менеджерам (менеджер видит своё), загрузка вперёд; экспорт CSV/Excel.

## 6. Надёжность
- Автосохранение каждой правки + офлайн-черновик локально с отправкой при связи (конфликт — побеждает последняя правка, событие в историю).
- Гейт деплоя Vercel по зелёному CI (сейчас нет — риск для «продажи встают»).
- Публичные ссылки КП — подписанный токен, срок жизни, отзыв.
- Эталоны: 3–5 реальных заказов с ценами и ТЗ → снапшот-тесты расчёта и генерации ТЗ. Без них рефакторинг цены слепой.
