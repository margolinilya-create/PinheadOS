## 1. Цель и пользователь

Снять три технических неизвестных до того, как на них завяжут срезы 1–4, и закрепить контракт данных между Order и ERP тестами. Интерфейс не меняется; пользователь среза — разработка и владелец, который принимает решения по итогам спайков.

**Критерий готовности:** три отчёта по спайкам с рекомендацией, эталонные тесты зелёные, миграции применены и сверены с продом, все сторожа проходят мутационную проверку.

## 2. Работы

### 2.1 Эталонные заказы → тесты (первое, до кода)
Владелец даёт 3–5 реальных заказов: PDF ТЗ + итоговая цена + сетка. Для каждого:
- фикстура `src/orderstudio/fixtures/<slug>.json` — заказ в модели v4 (позиции, сетка, нанесения, бирки, упаковка);
- снапшот-тест расчёта: `calcTotal` даёт ту же цену (допуск — округление до 5 ₽); расхождение = либо ошибка формулы, либо ручная цена в оригинале — фиксируется в фикстуре явно;
- те же фикстуры питают спайк PDF и тест контракта моста.

### 2.2 Спайк PDF — два пути, один отчёт
Собрать ТЗ «Дзен Арктика» (6 страниц: шапка, полотно и сетка, бирки, нанесения блоками, упаковка) двумя способами:
- **A. Клиент:** jsPDF + svg2pdf, кириллица через LiberationSans — движок из `PNHD-design-maker/lib/export`;
- **B. Сервер:** HTML-шаблон → edge-функция Supabase → PDF (Chromium в edge-runtime или внешний рендер).
Отчёт `docs/erp/2026-09-27-pdf-spike.md`: время сборки, размер файла, качество кириллицы и векторов, трудоёмкость вёрстки, поддержка многостраничности, стоимость на сервере. **Рекомендация одним предложением.** Ветку спайка не мержить.

### 2.3 Спайк konva в React 19
Под флагом `designMaker`: пустой холст react-konva, один флэт FreeFit из seed, перекраска, лениво. Проверить: совместимость react-konva с React 19 и Vite 7, `useShallow`-селекторы zustand 5, бюджет бандла CI (оболочка не растёт, холст — отдельный чанк), тач на планшете. Отчёт `docs/erp/2026-09-27-konva-spike.md` с рекомендацией: переносить как есть / переносить с заменой / отказаться от konva.

### 2.4 Контракт моста — `tzToErpDraft`
Чистая функция `src/orderstudio/bridge/tzToErpDraft.ts`: заказ v4 → `DraftForm` из `erp/utils/orderForm.ts`. Таблица маппинга (методы, зоны, бирки, упаковка, типы продукции, источник изделия) — данными, не ветвлениями. Тесты на граничные случаи спеки моста (раздел 6) + на эталонные фикстуры. **Сторож:** каждое поле `DraftItem` и `DraftForm` либо имеет источник в маппинге, либо явно перечислено в `NOT_FROM_ORDER` с причиной (`launch_date`, поля закупщика). Новое поле в ERP без решения роняет тест.

### 2.5 Миграции (аддитивные, применить до мержа, сверить md5 с продом)
1. `erp_order_items.sale_price_per_unit numeric null` — цена продажи; `erp_order_item_guard` на исключениях закрывает её по умолчанию; писатель — `erp_create_order` и право `order.manage`; `erp_item_economics` отдаёт маржу; тест стража.

## 3. Сценарии и граничные случаи
- Эталон с ручной ценой в оригинале — тест сравнивает расчётную и помечает ручную, не подгоняет формулу.
- Фикстура с двумя цветами одной модели — сетка цвет × размер, в `DraftGrid` одна позиция с несколькими строками.
- Фикстура с DTG — маршрут получает этап подряда, `erp_item_prints.method = 'dtg'` читается.
- Заказ без нанесений, аксессуар без ткани — контракт не падает, `purchase[]` пуст.
- Новое поле в `DraftItem` — сторож красный (проверить мутацией).
- Спайк PDF на пустых полях — документ собирается с прочерками, не падает.
