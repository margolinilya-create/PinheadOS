## 1. Цель и пользователь

Снять три технических неизвестных до того, как на них завяжут срезы 1–4, и закрепить контракт данных между Order и ERP тестами. Интерфейс не меняется; пользователь среза — разработка и владелец, который принимает решения по итогам спайков.

**Критерий готовности:** три отчёта по спайкам с рекомендацией, эталонные тесты зелёные, миграции применены и сверены с продом, все сторожа проходят мутационную проверку.

## 2. Работы

### 2.1 Эталонные заказы → тесты (первое, до кода)
**Сначала — чистая функция цены.** `calcTotal(state)` (`utils/pricing.ts:359`) принимает состояние визарда (`Record<string, any>`), а `getPrices()` читает `useStore`. Вынести `priceOrder(input, prices)` без стора; существующие тесты цены — регресс вынесения, `calcTotal` становится обёрткой.

Владелец даёт 3–5 реальных заказов: PDF ТЗ + итоговая цена + сетка. Для каждого:
- фикстура `src/orderstudio/fixtures/<slug>.json` — заказ в модели v4 (позиции, сетка, нанесения, бирки, упаковка);
- снапшот-тест расчёта: `priceOrder` даёт ту же цену (допуск — округление до 5 ₽); расхождение = либо ошибка формулы, либо ручная цена в оригинале — фиксируется в фикстуре явно;
- те же фикстуры питают спайк PDF и тест контракта моста.

### 2.2 Спайк PDF — два пути, один отчёт
Собрать ТЗ «Дзен Арктика» (6 страниц: шапка, полотно и сетка, бирки, нанесения блоками, упаковка) двумя способами:
- **A. Клиент:** jsPDF + svg2pdf, кириллица через LiberationSans — движок из `PNHD-design-maker/lib/export`; только ленивым чанком. Ограничение: `singleChunk` ≤ 100 000 Б gzip (`scripts/bundle-budget.mjs`), оболочка уже на 97 % бюджета — замер чанка обязателен;
- **B. Сервер:** pdf-lib в edge-функции — образец уже в проде: `supabase/functions/purchase-list-pdf` (pdf-lib + fontkit, DejaVu Sans, запись в `erp-attachments`). «HTML → Chromium в edge-runtime» не рассматривается: Chromium в Deno edge не запускается, внешний рендер — новая служба.
Отчёт `docs/erp/2026-09-27-pdf-spike.md`: время сборки, размер файла и чанка, качество кириллицы и векторов (SVG-макет нанесения в B — через растр или pdf-lib `drawSvgPath`), трудоёмкость вёрстки, многостраничность. **Рекомендация одним предложением.** Ветку спайка не мержить. Оценка — полсессии: путь B начинается с готовой функции.

### 2.4 Контракт моста — `tzToErpDraft`
Чистая функция `src/orderstudio/bridge/tzToErpDraft.ts`: заказ v4 → `DraftForm` из `erp/utils/orderForm.ts`. Таблица маппинга (методы, зоны, бирки, упаковка, типы продукции, источник изделия) — данными, не ветвлениями. Тесты на граничные случаи спеки моста (раздел 6) + на эталонные фикстуры. **Связь с Order:** серверная половина есть с 18.08 — `erp_create_order` читает `payload.order.tz_order_id`/`tz_number`, у `orders` есть `erp_order_id`, уникальный индекс по `tz_order_id` (`20260818203459_erp_order_from_tz.sql`); клиент их ни разу не слал. Маппинг заполняет оба поля, сторож проверяет это явно. Колонки позиции Order называть как в `DraftItem` — маппинг почти тождественный. **Сторож:** каждое поле `DraftItem` и `DraftForm` либо имеет источник в маппинге, либо явно перечислено в `NOT_FROM_ORDER` с причиной (`launch_date`, поля закупщика). Новое поле в ERP без решения роняет тест.

### 2.5 Миграции (аддитивные, применить до мержа, сверить md5 с продом)
1. **Цена продажи — отдельная таблица** `erp_order_item_prices` (`item_id` PK/FK, `sale_price_per_unit numeric not null`, автор, время), а не колонка позиции: `erp_order_items_read` = `erp_is_member()`, и колонка отдала бы цену любому рабочему через REST. SELECT — `economics.view`, запись — `erp_create_order` и `order.manage`; `erp_item_economics` отдаёт маржу по этой таблице; политики на команду, вызов функции в `(select …)`; тест прав.
2. **Гейт деплоя Vercel по CI** — прод выкатывается только с зелёного `main` (сейчас `vercel.json` выкатывает на push без CI). Не миграция, но в этом же PR.

**Отложено (сверка 28.09) — делается в срезе, который это использует:**
- право `sku.geometry` — срез 4: колонок геометрии у `erp_sku_cards` нет, ролей technologist/designer в `erp_employees` на бою ни у кого нет;
- виды `erp_dictionaries` (`blank`, `print_zone`, `print_place`, `label_place`, `packaging_kind`, `packaging_insert`, `pantone`, `product_type.meta.marking`) — срезы 1 и 3, каждый вместе с экраном, который из него читает. `label_type` **уже существует** (5 значений) — не заводить. CHECK видов расширять новой миграцией вместе с TS-союзом `DictionaryKind`;
- `erp_notifications.kind` — срезы 2–3, вместе с писателем каждого вида;
- DTG как подряд — срез 3: участок выключен 07.09, DTG-нанесений на бою ноль; `routeDraft` требует у шага `executor = contractor` подрядчика и операцию — спека среза 3 решает, откуда они берутся.

## 3. Сценарии и граничные случаи
- Эталон с ручной ценой в оригинале — тест сравнивает расчётную и помечает ручную, не подгоняет формулу.
- Фикстура с двумя цветами одной модели — сетка цвет × размер, в `DraftGrid` одна позиция с несколькими строками.
- Фикстура с DTG — в срезе 0 контракт переносит `method = 'dtg'` как есть, этап подряда — срез 3.
- Рабочий цеха читает `erp_order_item_prices` через REST — пусто (тест прав).
- Заказ без нанесений, аксессуар без ткани — контракт не падает, `purchase[]` пуст.
- Новое поле в `DraftItem` — сторож красный (проверить мутацией).
- Спайк PDF на пустых полях — документ собирается с прочерками, не падает.
