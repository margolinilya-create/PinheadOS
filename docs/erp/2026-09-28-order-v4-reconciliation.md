# Сверка Order v4 и среза 0 с репозиторием и боем
**Дата:** 28.09.2026 · main на `556f5f0` (#190) · база `pinhead-os-v2`
**Что сверялось:** `2026-09-27-order-v4-structure.md`, `2026-09-27-plan-review.md`,
`2026-09-27-order-slice-0-spec.md`.

Направление верное: срезы вместо слоёв, контракт моста раньше дизайн-мейкера,
эталонные заказы до кода. Но спека среза 0 опирается на несколько неверных фактов,
а у плана есть одна архитектурная дыра, которую документы не называют.
Правки ниже уже внесены в спеку среза 0 и в v4 (§5, §8).

---

## 1. Главное: у заказа продаж до запуска нет ни чата, ни уведомлений

- `erp_chat_threads.order_id` → `erp_orders` (`20260914221959_erp_chat_core.sql:23`),
  `erp_notifications.order_id` → `erp_orders` (`20260914214651_erp_notifications.sql:39`).
- До запуска у Order-заказа нет строки `erp_orders`, поэтому v4 §5 «чат, уведомления —
  переиспользуются из ERP» в лоб не работает.
- Завести заказ продаж сразу в `erp_orders` тоже нельзя: SELECT у `erp_orders`,
  `erp_order_items` и `erp_chat_threads` на бою — `erp_is_member()`, то есть КП, цена
  и переписка по сделке были бы видны каждому рабочему цеха. «Только свои» так не получится.

**Решение в духе существующей схемы.** Тред уже задуман отвязываемым: сообщение принадлежит
ТРЕДУ, а не заказу (правка 14.09). Треду и уведомлению нужна вторая ссылка — `sales_order_id`,
а в политике чтения — отдельная ветка «тред продаж → предикат видимости Order». При запуске
тред получает `order_id` производственного заказа, переписка не копируется. Место — срез 2
(«чат сделки»), а не общая фраза про переиспользование.

## 3. Что поменять в составе среза 0

**Добавить**
- **Гейт деплоя Vercel по CI.** v4 §6 его требует, в спеке он пропущен; `vercel.json`
  выкатывает на push без CI. Для «продажи встают» это дешевле всего остального.
- **Чистая функция цены.** `calcTotal(state)` (`utils/pricing.ts:359`) принимает состояние
  визарда (`PricingState = Record<string, any>`, `:22`), а `getPrices()` читает `useStore`
  (`:63-66`). Снапшот-тест фикстуры v4 без неё не написать. Нужен `priceOrder(input, prices)`
  без стора; существующие тесты цены — регресс вынесения.

**Отложить до среза, который это использует**
- 7 новых видов `erp_notifications.kind` — писателей нет до срезов 2–3.
- 8 видов справочников с пустыми сидами — пустой справочник в админке никто не заполнит,
  пока нет экрана, который из него читает.
- Право `sku.geometry` — колонок геометрии у `erp_sku_cards` нет (`20260915030910_erp_sku_cards.sql`),
  выдавать некому (см. роли).

**Перенести в срез 3: DTG как подряд.** Участок выключен решением 07.09
(`20260907182524_erp_dtg_off.sql`), DTG-нанесений на бою ноль. И технически пункт не
однострочный: `BRANDING_DEPT.dtg → 'outsource'` даст шаг с `executor = contractor`, а
`routeDraft` требует у такого шага подрядчика и операцию — иначе маршрут не соберётся.
Спека должна сказать, откуда их взять.

## 4. Решения за владельцем

1. **Права Order** — через ту же матрицу `erp_has_permission` (новые ключи `sales.*`),
   а не по `profiles.role`. Рекомендация — да: одна матрица, один сторож
   `serverPermissions.test.ts`.
2. **Имена колонок позиции Order — 1:1 как в `DraftItem`** (`erp/utils/orderForm.ts:101`).
   Тогда мост почти тождественный, а сторож контракта — сравнение ключей.
3. **Ужать срез 1.** Пока пилотирует один владелец, «только свои» и офлайн не нужны —
   в срез 3, где подключается второй менеджер. Первое реальное КП — сессии на 2–3 раньше.
